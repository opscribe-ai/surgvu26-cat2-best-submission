SurgVU 2026 · Category 2 · Build guide

How each step works, and why we need it

Written so you can draw the architecture yourself. Every step gets a plain-English description, a concrete example of what goes wrong without it, and exactly what flows in and out -- so the boxes and arrows draw themselves.

The whole thing in one paragraph

The challenge hands us a 30-second clip of robotic surgery and one question about it. We hand back one short answer. A computer then checks how close our answer is in meaning to any of five acceptable answers it has on file.

The key thing we worked out: those five answers were not written by anyone watching the video. They were written by someone reading a logbook -- a spreadsheet recording which instruments were plugged into the robot, and which training exercise was underway. So our real job isn't "understand this surgery." It's work out what the logbook said.

The one idea the diagram has to communicate:

Some questions are answered by looking. Some are answered by checking records. Looking is expensive, so we only do it when looking would actually help.

A doctor X-rays to find a broken bone. A doctor does not X-ray to find a blood type -- that's on the chart. If your diagram makes that split obvious, it's working.

One useful way to describe the whole thing: it's a mixture of experts. Rather than one enormous model that tries to do everything, we keep a bench of narrow specialists -- an instrument reader, an exercise reader, a detector, an action model, a set of lookup tables, and one general-purpose language model -- and the question parser decides which specialists get called for this particular question.

One precision, for the write-up

In the literature "mixture of experts" usually means a learned gate over expert sub-networks trained together. Ours is a hand-written gate over separately-trained specialists, which is more precisely a hard-routed expert ensemble. Worth saying it that way in the report so a reviewer doesn't. Taking the framing seriously does suggest an upgrade though: if it's a gate, why is it hand-written? We ship the rule-based version first, then train a gate and see if it beats it.

The nine steps

1
Read the questionplain code
Python rules + a YAML list of tool names · no model, no GPU, microseconds

Before touching the video, sort the question into a type. Is it yes/no? Is it asking for an organ name? Is it asking something general about surgery that has nothing to do with this clip? Also pull out what it's asking about -- "forceps," "needle driver," "organ."

Without it

The question "What is the purpose of using forceps?" is general medical knowledge -- the video is irrelevant. With no sorting step, we'd run the whole expensive pipeline on it anyway, and worse, we'd let what we saw in the clip contaminate a textbook answer.

in question textout question type + what it's asking about
2
See which instruments are plugged inwe train this
CNN image classifier (EfficientNetV2-S, ~22M params) · we train it · GPU, milliseconds

A small image model looks at frames from the clip and names the three instruments mounted on the robot. Always exactly three -- the da Vinci has four arms and one holds the camera, so three carry tools.

Concretely: the model outputs 12 numbers, one per possible instrument, each a probability. We train it against a target that has three of those set high, and at the end we take the top three. So the "exactly three" fact lives in both the training target and the final selection -- it isn't something we hope the model figures out. (A neater variant gives the model three separate 12-way outputs, one per robot arm, since the logbook records which arm each tool sits on. Elegant, but the model can't tell which arm it's looking at, so it needs extra machinery. Worth trying second.)

Without it

The big AI model has to identify surgical instruments from raw pixels, which it is genuinely bad at -- a needle driver and a bipolar forceps look nearly identical at endoscope resolution. Adding this one component is essentially the entire reason last year's winner won.

in video framesout three instrument names
3
Identify which exercise this iswe train this
a second CNN image classifier, same backbone, 8-way · we train it · GPU, milliseconds

A second small model decides which training exercise is happening: suturing, uterine-horn dissection, rectal artery/vein, range of motion, and so on. Eight options.

Without it

Two things break. We can't look up the description in step 4 -- which is the single biggest advantage we have. And questions like "Which surgical specialty is this?" become unanswerable, because the answer follows from the exercise, not from anything visible on screen.

in video framesout exercise name
4
Look up the official descriptionplain code
a YAML file with 21 entries + about five lines of Python · no model, microseconds

Across the entire dataset there are only 21 possible descriptions of what's happening. Twenty-one, total. So once we know the exercise, we look up the exact paragraph that goes with it -- and that paragraph is the very text the graders were reading when they wrote the correct answers. It's a dictionary lookup, nothing more.

Without it

We'd be guessing at wording the graders derived from a specific paragraph we could simply have read. Last year's winner saw the same 21 descriptions, judged the dataset "too small to train on," and threw them away. They aren't a training set -- they're the answer key.

in exercise nameout the official description paragraph
5
Ask the big modelpartner owns this
VLM -- a ~7B-parameter transformer, 4-bit NF4, off the shelf · GPU, seconds

Now hand everything to the large vision-language model: the frames, the three instrument names, the official description, and the question. It gives back a short answer.

We run it at 4-bit. Models store their numbers at a chosen precision, and squeezing them smaller trades a little accuracy for a lot of memory. At full precision a 7B model needs about 14 GB -- the GPU we're given has 16 GB, and we also need room for the video frames and the two CNNs. It won't fit. Half-size (8-bit) fits but runs slowly. Quarter-size (4-bit) needs about 4 GB, leaves plenty of headroom, and is exactly what won this challenge last year. This is decided -- not something to experiment with.

Without it

We'd have a pile of facts and no way to combine them into an answer to an arbitrary question. Steps 2–4 produce ingredients; this is what cooks with them.

in frames + instruments + description + questionout a candidate answer
6
Work out whether it's actually surepartner owns this
Python arithmetic over N model outputs · no model of its own, but it costs N× the VLM

We need a number saying how much to trust step 5. Our working proposal is to ask the model the same question several times, each time showing it a different set of frames. Same answer every time means it knows. Flip-flopping means it's guessing. We don't ask the model "how confident are you?" -- models are notoriously bad at answering that honestly.

Without it

We can't tell a confident right answer from a coin flip. That leaves two bad options: double-check everything, which we can't afford on the small GPU they give us, or double-check nothing, which means occluded instruments get called absent all day.

in several answers to the same questionout a confidence number
7
Decide: would looking harder help?plain code
Python if/else + thresholds in a YAML file · no model, no GPU, microseconds

Compare the model's answer against what steps 2 and 3 found. If they agree and confidence is high, we're done -- emit the answer. If they disagree, or the model was flip-flopping, we ask one question before spending anything: could we find this out by looking at the video longer or harder?

If yes, go to step 8a. If no, go to step 8b. That single question is the whole design.

Without it

We'd spend identical effort on every question. Roughly four in five are easy -- they'd eat the entire compute budget, leaving nothing for the hard fifth that actually needed it. Worse, we'd run the expensive detector on questions it physically cannot answer, and it would hand back misleading evidence.

in answer + confidence + instruments + question typeout emit, or which branch
8a
Call in a specialistwe train two of these
CNN object detector (YOLO- or DINO-family) · temporal CNN · or just more frames

Three specialists the router can call, depending on what's in doubt.

  • Object detector -- hunts specifically for the one instrument the question asked about. Useful because the whole-frame model in step 2 squashes everything down and misses a tool that's mostly hidden or at the edge of view, whereas a detector scores small regions and can catch it.
  • Action model -- a small CNN that watches motion across many frames and answers "is tissue being cut?" directly. Purpose-built for exactly that, so it's faster and more accurate than asking a general 7B model.
  • More frames -- sometimes we just sampled badly. Decode thirty frames instead of five and re-ask.
The distinction that decides the arrow

The detector and the extra frames give the VLM something new to look at, so they hand back to VLM Pass 2. The action model gives us the answer itself, so it goes straight to Answer Form -- no second pass. Same rule as the records branch: only re-ask the model when it has something new to weigh.

Without it

An instrument that's plugged in but hidden behind tissue gets called absent. Since the logbook says it's there, the correct answer is "yes" -- so this is the single most common way to be wrong.

in the specific thing in doubtout evidence → re-answered, or the answer directly
8b
Check the records insteadplain code
YAML lookups + counting from tools.csv · Python, no model, microseconds

Some questions can't be answered by looking, no matter how long you look. Those get resolved from our tables -- either by answering at the level we can actually see, or by trusting the exercise classifier over the big model.

Notice this branch skips the second model pass entirely. Nothing new was seen, so re-asking would just cost time and give the model a chance to talk itself out of an answer that's already right.

Without it

"Is a large needle driver installed?" -- we can see a needle driver plainly. But Large vs Mega vs Large SutureCut differ by a few millimetres of shaft and a part number stamped where no endoscope will ever see it. Send that to the detector and you burn the budget to learn nothing.

in question type + what we already knowout resolved answer, straight to step 9
9
Say it in as few words as possibleplain code
a YAML file of answer shapes + string formatting in Python · no model

One of the five accepted answers is always the bare form -- just "Yes", or just "Uterine horn". An exact match scores perfect. So for most question types we emit a single word. Only explanation-type questions get a full sentence.

Without it

You write a well-formed, medically accurate sentence -- and score lower than someone who typed "Yes." Saying more than necessary can only lose points.

in question type + the resolved answerout the final text we submit

What each kind of thing actually is

Only four kinds of thing appear in this whole system. Worth knowing which is which, because they differ in cost by a factor of about a thousand.

KindIn plain terms
YAML file A plain text file holding a list or a table, readable by a human in a text editor. Ours hold the 21 descriptions, the tool names, the answer shapes, and the router's thresholds. Not a program and not a model -- just written-down facts we can edit without touching code.
Python code Ordinary programming. Rules, if statements, counting, string handling. Deterministic -- same input always gives the same output -- and effectively free to run.
CNN Convolutional neural network. An image model that takes a picture and outputs a label ("this frame contains a needle driver"). Small -- tens of millions of numbers. We train these ourselves on the challenge's video. Fast: milliseconds per frame.
VLM Vision-language model. Takes pictures and text and writes an answer in English. Huge by comparison -- billions of numbers. We use one off the shelf, unmodified. Slow: seconds per call, and it's the only thing here that can actually compose an answer to an arbitrary question.

The number that explains the whole design

The VLM costs roughly a thousand times more than everything else combined. Every other box on the diagram is free by comparison. So the entire architecture is really one question: how few times can we call the VLM and still be right?

That's why steps 2, 3 and 4 exist -- they hand the VLM the answer on a plate so it doesn't have to work it out. It's why step 9 caps the answer at a word or two. And it's why the router refuses to run a second pass on the records branch, where the second pass would learn nothing.

Why this matters for the confidence workstream

Only three of the thirteen rows above cost anything: the two VLM passes and the detector. Everything else is free. So the confidence method is effectively the budget -- checking consistency across five frame-subsets means five VLM calls, which is five times the cost of the naive approach. Whatever method your partner picks, its price is measured in VLM calls, and that's the number that has to fit inside the per-clip time limit.

Which branch, with real questions

This is the part worth getting right in the drawing, so here it is concretely. The test is always the same: could you find out by looking at the video longer or harder?

QuestionBranchWhy
"Are forceps involved in the procedure?" LOOK HARDER A forceps is a physical object in the frame. It might be behind tissue or at the edge of view in the five frames we sampled. More looking genuinely changes the answer.
"Is tissue being cut during this clip?" LOOK HARDER
(action model)		 Cutting might last three seconds out of thirty, so five frames can miss it. But this is a motion question, so a purpose-built action model answers it directly -- no need to involve the big model at all.
"What organ is being manipulated?" LOOK HARDER The organ is physically on screen. Better angles and more frames help.
"Is a large needle driver among the listed tools?" RECORDS We can see a needle driver. Which model it is comes down to millimetres and a part number no camera can read. A thousand more frames tells you nothing.
"Which surgical specialty is this associated with?" RECORDS No pixel anywhere says "gynecology." It follows from knowing the exercise, which we already determined in step 3.
"What is the purpose of using forceps?" RECORDS Textbook knowledge. The video is irrelevant -- this one never touches the video pipeline at all.
The bit that trips people up

"Are forceps involved?" goes to LOOK HARDER, but "Is a large needle driver involved?" goes to RECORDS -- even though both are "is this tool present?" questions. The first asks about a kind of object, which is visible. The second asks which model of that object, which is paperwork. Presence-of-a-kind is visible. Which-model-of-that-kind is a catalogue fact.

Three questions, start to finish

"Are forceps involved in the procedure?"
The easy path -- about 4 in 5 questions
  1. Read it → yes/no question, about forceps.
  2. Instruments → needle driver, monopolar curved scissors, prograsp forceps. A forceps is there.
  3. Exercise → suturing. Look up → the suturing paragraph.
  4. Ask the model, five times on different frames → Yes, Yes, Yes, Yes, Yes.
  5. Router → model says yes, instruments say yes, no flip-flopping. Agree. Stop here.
  6. Say it briefly → "Yes".
→ "Yes"  ·  exact match with an accepted answer  ·  perfect score
"Are forceps involved in the procedure?"
Same question, harder clip -- looking helps
  1. Instruments → needle driver, monopolar curved scissors, clip applier. No forceps found.
  2. Ask the model, five times → Yes, No, Yes, Yes, No. It's guessing.
  3. Router → they disagree and confidence is low. Could looking harder settle it? Yes -- a forceps is a physical object. Escalate.
  4. Detector → hunts only for forceps. Finds a bipolar forceps in frame 12, mostly behind tissue -- exactly why the whole-frame model missed it.
  5. Ask again, now told a forceps was detected → Yes, confidently.
→ "Yes"  ·  would have been wrong without step 8a
"Which surgical specialty is this procedure associated with?"
The records path -- no second look, ever
  1. Read it → specialty question. Not about instruments at all.
  2. Exercise → uterine horn dissection.
  3. Ask the model → it says "urology." The classifier implies gynecology. They disagree.
  4. Router → could looking harder settle this? No. Nothing on screen names a specialty. Don't buy evidence -- and on this branch the exercise classifier outranks the big model.
  5. Records → uterine horn → gynecology. Straight to the answer, no second model pass.
→ "Gynecology"  ·  the model was overruled, correctly

Arrow labels worth writing on -- the rest can stay unlabelled:

  • Question parser → Router: question type -- easy to forget, and the router can't work without it
  • Router → Answer form: agree -- emit
  • Router → upper lane: looking would help
  • Router → lower lane: looking can't help
  • Lower lane → Answer form: no second pass
  • Action model → Answer form: answers directly
Two arrows that are easy to get backwards

The question parser must feed the Router, not just the VLM. The router decides which lane to take, and that decision is driven by the question type -- without that arrow the router has only an answer and a confidence number, which isn't enough to choose a branch.

The records branch must NOT pass through VLM Pass 2. Table Lookups goes straight to Answer Form. If the drawing routes it through the model, it says the opposite of the design's main claim.

Three things that make or break the drawing:

  1. Draw the two lanes as visibly separate -- a shaded band, a dividing line, two colours. Label them LOOKING HELPS and LOOKING CAN'T HELP. This is the idea; everything else is plumbing.
  2. Put "VLM -- second pass" only in the upper lane. If it sits under both, the diagram says the opposite of what we mean.
  3. Make the agree-path visually dominant -- thicker, or the only coloured arrow. It's what happens most of the time, and a reader should see that instantly.

Consider colour-coding by what each box is -- one colour for CNNs, one for the VLM, one for the plain Python and YAML boxes. It makes an obvious point without a word of explanation: only three boxes are expensive, and everything else is nearly free.

Leave out: the Docker container, the GPU, and the individual YAML filenames. They're real but they're not the argument, and they'll crowd the picture.

Boxes your partner owns

VLM -- first pass, Confidence check, and VLM -- second pass are open. Which model, and how confidence gets measured, is their call. Draw them as boxes with the arrows in and out fixed -- the rest of the design doesn't change whatever they pick. All the router needs from them is an answer and a number from 0 to 1.
