The v4 Signal Path

Every step the container takes between a 30-second surgical clip and the one string we submit — what each step buys, what it costs, and where new machinery can actually reach the score.

video (1800 frames) → 16 frames → ~20 numbers → 1 of 12 recipes → 1 of ~20 strings
                             └─── the bottleneck ───┘  └─── the ceiling ───┘

Before the steps: what a point is worth

The pros and cons below are unreadable without this. The metric is BERTScore-F1 against five references, and it takes the maximum. Reference one is always the terse answer, so an exact "Yes" scores 1.0000. Measured on the eleven public cases:

SituationScoreWhat it means
Polar question, right1.0000exact match on reference one
Polar question, wrong0.7015“Yes” and “No” are semantically close — being backwards is cheap
Open question, right1.0000
Open question, wrong specific noun0.2402“Bipolar Forceps” when gold is “Cadiere Forceps”
Open question, generic sentence0.2562higher than being confidently wrong
Empty or missing answercrashthe scorer dies; the case is worth nothing

So the stakes per question type are wildly unequal: 0.2985 rides on a polar answer, 0.7598 on an open one. Open questions are worth two and a half times as much — and almost the entire engineering effort of this project has gone into tool-presence perception, which only ever feeds polar questions.

The number that frames everything below

A version of this pipeline that never opens the video — question text and hard-coded constants only — scores 0.8294 on the eleven public cases. The full v4 with both CNNs scores 0.8766.

Every model in this project is worth +0.0472. The leaderboard has returned 0.8015 three times, from three different builds.

The pipeline, in order

00
Contract

The container wakes up, once per case

Grand Challenge starts the container fresh for every single case and hands it exactly two files: a 30-second MP4 and a JSON file holding one question string. It writes one JSON file holding one answer string. Then it dies.

read   /input/endoscopic-robotic-surgery-video.mp4
read   /input/visual-context-question.json     ← a JSON-encoded STRING
write  /output/visual-context-response.json    ← a JSON-encoded STRING

Budget: 10 minutes, 32 GB RAM, either one T4 GPU or no GPU at all. The T4 is sm_75 — no bf16, no FlashAttention-2.

Buys

  • Dead simple contract. Nothing to orchestrate, nothing to batch.
  • One case failing cannot take another case with it.

Costs

  • Model loading is paid fresh every case — nothing amortises. This is what makes a large VLM an expensive question rather than a free one.
  • Both JSON files hold encoded strings. Writing bare Yes instead of "Yes" is malformed JSON and scores zero however right the answer was.
01
Shapes the answer

Decode sixteen frames

Open the MP4, count its frames, pick 16 evenly spaced across the full 30 seconds, decode only those. Each one gets its black side pillars cropped and its bottom UI band blurred out — that is a challenge rule, not an optimisation. We are not allowed to read instrument names off the on-screen display, so there is deliberately no code path into a model that skips the blur.

Sampling is by frame index, not by timestamp, so the same code covers the 60 fps sample clips and the 1 fps test clips without a hidden time-base bug. A frame whose seek fails is skipped rather than ending the clip.

Buys

  • About one second of wall clock against a 600-second budget.
  • Covers the whole clip instead of one moment.
  • Robust to a corrupt frame late in the file.

Costs

  • 16 of 1800 frames is 0.9% of the video. Anything between samples is invisible.
  • A 30-second clip is a story — a tool enters, acts, leaves. Sixteen stills are handed downstream as an unordered bag, and the ordering is never recovered.
01b
Optional branch

The motion branch grabs neighbours

With --motion on — it is on in v4 — the decoder also grabs each sampled moment’s two neighbours at ±67 ms. Sixteen “bursts” of three frames, 48 frames instead of 16.

burst 0          burst 1          burst 2    ...    burst 15
[t-67  t  t+67]  [t-67  t  t+67]  [ ... ]           [ ... ]
 └─── 0.2 s ───┘
         └─────────── 1.875 s apart ───────────┘

The safety contract: the 16 centre frames are byte-identical to what plain decoding produces. The CNNs see exactly the same input either way, and a test asserts that rather than trusting it — so turning motion on physically cannot move an appearance-model answer.

A burst whose flank fails to read is recorded as None — “unmeasurable”, not “still”. Same at the clip edges, where it refuses to clamp, because differencing a frame against itself would read as perfect stillness: a lie with a plausible value.

Buys

  • Measured cost is +6% — 6.6 s to 7.0 s per case. Cost was never the argument against this.
  • Zero blast radius on the shipped appearance path, by construction.

Costs

  • Three times the video seeks, and seeking is the slow half of decoding.
01c
Optional branch

Two motion numbers, computed not learned

Every frame shrinks to 64×64 grayscale; take the mean absolute pixel difference between consecutive frames. That is the entire algorithm. No network, no labels, no training, nothing to overfit, and nothing that goes stale when a checkpoint is retrained.

MeasuresCountHigh means
microinside one burst, 67 ms apart16something is moving right now
macrobetween burst centres, 1.875 s apart15the scene is changing across the clip

They are not redundant. Micro-still and macro-active is a camera cut. Micro-active and macro-still is sustained work in one place — which is what active surgery looks like. Units are 0–255 brightness difference, chosen so the number is comparable across cases with no per-case calibration.

Buys

  • Free, instant, deterministic, and immune to a retrain invalidating it.
  • Genuinely the right first move at supplying event evidence.

Costs

  • It cannot tell camera motion from instrument motion. A scope push moves every pixel and reads as maximum activity. Separating them needs optical flow or a learned model.
  • 64×64 is coarse — a needle tip travelling three millimetres may not cross a single pixel.
02
Shapes the answer

Two CNNs look at the frames

Each of the 16 frames passes through two separate ResNet-50 networks, both at 384×384:

HeadShapeAsksValidation
Toolsmulti-label, 12 outputs, sigmoidwhich instruments are installed0.7673 macro-F1
Taskmulti-class, 8 outputs, softmaxwhich activity is this0.9454 accuracy

The activations are not interchangeable: several instruments are installed at once, so they must not compete for one unit of probability mass; one activity is happening, so they must.

Buys

  • Small, fast, reliable, runs on CPU if the GPU is missing.
  • Well validated across 4,635 held-out windows.

Costs

  • These are the only two questions the system can ever ask of the video. Not what the surgeon is doing with the tool, not whether it is moving, not what tissue that is — just which of 12 instruments and which of 8 activities. Everything downstream is a rearrangement of those twenty numbers.
  • The 12 classes are classes, not products. “Large Needle Driver”, “Mega Needle Driver” and “SutureCut” all collapse into needle driver. Three of the eleven public questions name a variant, and the distinction is not recoverable from the model output at all — it is answered from the class with a measured 6.9% error.
03
Decides the answer

Squash sixteen frames into one number per class

Average the 16 per-frame probabilities into a single clip-level probability, then apply a per-class threshold to decide which tools count as present. The thresholds are tuned individually and span 0.05 to 0.95, because the corpus is ninety-fold imbalanced and a shared 0.5 would drop every rare class while admitting every common one — and still produce a list that looks entirely reasonable.

Buys

  • Averaging probabilities is the right reduction; re-tuning the cuts to the clip mean is worth +0.0196 macro-F1 for no retrain.
  • Turns a variable-length clip into a fixed record the router can be tested against.

Costs

  • This is where time dies. After the mean, a clip and its exact reverse produce identical numbers. Motion, order, “the scissors closed” — all gone.
  • The threshold is a cliff. 0.36 versus 0.34 flips a tool from present to absent, and that flip is worth 0.2985 or 0.7598 depending on the question. Every gradation of confidence is discarded here — which is exactly the information a confidence-aware answer layer would need.
04
Plug-in point

The perception record — the bottleneck

Everything above collapses into one small dictionary. This is the entire memory of the video. Nothing downstream ever re-opens the file.

{
  tools:         {bipolar forceps: 0.12, cadiere forceps: 0.88, ...12 floats},
  tools_present: ["cadiere forceps", "needle driver"],
  task:          {suturing: 0.91, ...8 floats},
  task_top:      "suturing",
  n_frames:      16,
  motion: {                                   ← only with --motion
    bursts: 16,  bursts_measured: 14,
    micro: {per_burst: [16 floats], mean: 2.97, max: ..., std: ...},
    macro: {per_gap:   [15 floats], mean: ..., max: ..., std: ...}
  }
}

The motion block is purely additive — omit it and the record is byte-identical to the pre-motion version, same keys, same order, same values.

Buys

  • A clean seam. The router is fast, deterministic and testable because it reads a dict, not a video.
  • This record is what gets logged and diffed between builds — it is how we know six perception changes reached zero answers.

Costs

  • Whatever is not in this dict cannot influence the answer, ever. No boxes, no spatial layout, no counts, no per-instance confidence, no text, no scene description.
  • The router reads exactly one number out of the whole motion block — micro.mean. The macro statistic, the per-burst array, max, std and bursts_measured are all computed, all stored, and none of them are consumed by anything. That is unfinished, not broken — and it means the data is already there for free.
05
Plug-in point

Classify the question with regexes

A chain of regular expressions reads the question text — and only the question text — and sorts it into one of twelve intents:

polar:  tool_presence · cutting · suture · unknown_polar
open:   tool_identity · organ · procedure · purpose
        task · count · unknown_open

Order is hand-tuned and load-bearing: count before the tool rules because “how many instruments” contains “instruments”; organ before procedure because “what organ is manipulated in this procedure” contains “procedure”. A separate guard sends when / where / who / how long / which arm straight to unknown_open.

Buys

  • Instant, free, fully deterministic, and it never fails — it still works when everything else in the container has crashed, which is what makes the safety net intelligent rather than blind.

Costs

  • It only recognises what someone thought to write a pattern for. Validated against eleven real questions and some synthetic probes.
  • We have never measured what fraction of the hidden test set lands in unknown_open and receives one fixed sentence worth 0.2562–0.4436.
  • It fails silently. An off-pattern phrasing drops to a fallback and nothing anywhere reports that it happened.
06
Decides the answer

Each intent has a hard-coded recipe

IntentHow the answer is builtReads video?
tool presenceis the named tool in tools_present → Yes / Noyes
cuttingcutting tool present and scene moving → Yes / Noyes
suturetask is suturing, or a needle driver is presentyes
tool identityhighest-scoring tool class → its display nameyes
organtask_top → 8-entry lookup table → organ nameyes
countsize of tools_present, written as a wordyes
tasktask_top → display nameyes
procedurea constant string. Always the same.no
purposelook up the tool the question named → canned sentenceno
unknown polarconstant “Yes”no
unknown openconstant generic sentenceno

This is also the only place motion is consumed, and it is one branch of one recipe:

def _answer_cutting(question, perception):
    if not (credible_tools(perception) & CUTTING_TOOLS):
        return "No"                       # no scissors -> No
    if scene_is_static(perception) is True:
        return "No"                       # scissors, but nothing moving -> No
    return "Yes"

scene_is_static is tri-state, and the third state is the important one:

micro.mean < 1.283                     → True   "still"    ← the ONLY state that
micro.mean ≥ 1.283                    → False  "moving"      changes an answer
no motion block, or threshold = None   → None   "cannot know" → fall through

The threshold 1.283 is the tenth percentile of the eleven graded clips, not of training. Training’s bottom decile is 2.512, but graded clips are systematically calmer — median 2.970 against training’s 4.326 — so 2.512 would have fired on 27% of them instead of the intended 10%.

Buys

  • Every recipe was measured, not guessed. procedure returns the literal gold answer and scores 1.0000 on every case, forever.
  • Degrades gracefully — bad perception yields a mediocre answer, never a crash.
  • The cutting rule closes a real conceptual gap: an event question was being answered by a presence proxy, and no improvement to the tool head could ever have fixed that.

Costs

  • The entire output vocabulary is about twenty strings — Yes, No, 12 tool names, 8 organ names, four constants. This is why three genuinely different systems produced byte-identical output.
  • There is no “unsure” state anywhere in here. We now know that costs us: a confidently wrong noun on an open question scores 0.2402, below the 0.2562 of saying nothing.
  • The motion gate fires on zero of the eleven graded cases, flips roughly one cutting answer in ten from Yes to No on unseen data against a corpus whose golds skew Yes, and there is no cutting label in this corpus — so not one flip can be checked offline.
07
Decides the answer

Negation flip

If the question carries an existential negation — “Is there no needle driver?” — flip Yes/No. Applied centrally, after the recipe, so one rule covers every polar intent and cannot be half-implemented across them. It deliberately does not apply to the unknown_polar constant: flipping a calibrated guess just moves the coin to the side the corpus does not favour.

Buys

  • Correct, cheap, and structurally impossible to apply inconsistently.

Costs

  • Regex-detected, so it inherits every brittleness of step 05.
08
Mechanical

Finalise and write

Capitalise, collapse whitespace, and json.dump it — which is what puts the quotes on. One exit point, and it is impossible for it to write an empty string: an empty answer is replaced by the generic fallback, because an empty string crashes the scorer outright.

Wrapped around all of it

△
Safety net

Any failure still produces an answer

The whole pipeline sits inside a try/except. Unreadable video, missing checkpoint, CUDA error, our own bug — it logs loudly to stderr, writes an intent-aware fallback, and exits 0.

Intent-aware matters: questions whose recipe never consulted the video anyway (procedure, purpose) are still routed properly and still score 1.0000 even with a dead video. Everything else takes the calibrated floor — “Yes” if polar, the generic sentence otherwise — because re-routing a presence question against an empty record answers “No” to everything, and the golds skew Yes.

Buys

  • Genuinely excellent engineering, and why we have never scored a zero. A crash converts a ~0.70 case into 0.00.

Costs

  • It is so good at hiding failure that a broken pipeline and a working one look similar from outside. We would not necessarily know if perception had silently died.
◇
Built · OFF

The VLM seam

A --vlm flag already exists, wired and tested. When on, a Qwen VLM is offered only unknown_open questions — the ones where the alternative is that single generic sentence. It receives the blurred, preprocessed frames, never the raw video, so it cannot read the UI. Returning nothing, or raising, costs nothing: the router’s answer stands.

Two measured findings sit on it. Putting perception facts in the prompt made it worse — asked “what procedure is this?” with task_top = rectal artery/vein in context, it answered “Rectal artery/vein dissection using bipolar forceps” for 0.0834, against the 0.4790 the generic sentence gets. Without the context line, the same weights scored 0.4015. And on/off is byte-identical across all eleven sample cases.

Buys

  • The seam exists, is tested, and is fail-safe by construction.
  • Construction is free — no import, no weights, no CUDA context until an unrouted question actually arrives.

Costs

  • It is gated so narrowly that it can never fire on any question type we have ever observed. A door with no room behind it.
  • Naming perception in the prompt invites the model to parrot a taxonomy label as if it were an answer.

Where new work can actually reach the score

Three seams, and only three. Everything between them is plumbing that works.

SeamStepWhat lands thereWhy it reaches the score
The record04 YOLO boxes, per-instance confidence, counts, spatial layout, the unused motion statistics Anything that becomes a key in this dict is visible to every recipe. Anything that does not is invisible forever.
Intent coverage05 a wider or learned question classifier; measuring what actually lands in unknown_open An unrecognised question is worth 0.2562–0.4436 no matter how good perception is. We do not know how often that happens.
The answer layer06 an “unsure” state, confidence-gated abstention, a wider output vocabulary, the VLM ungated Open questions carry 0.7598 each and abstention beats a wrong noun. This is the only step that can change what the system is allowed to say.
The one-sentence version

The pipeline is a well-built funnel that narrows an 1800-frame video to twenty numbers and then to one of about twenty strings — and the last three submissions proved that improving what enters the funnel does not change what leaves it.
